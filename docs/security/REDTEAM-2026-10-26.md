## Findings

### F1 — `..` defeats the new Google-Photos viewer gate: a live viewer reads EVERY album (disabled/unused) + all manifests — CONFIRMED (High)
**Severity: High.** Incomplete fix. Re-opens the exact class the previous run reported as CONFIRMED and that commit `1c70bd9` ("live viewers can no longer read a disabled/unused Google Photos album") was meant to close. A live viewer (anyone holding the live word — shared with parents, forwardable) can read the cached photos of **every** album, including the ones an admin deliberately **disabled** or never put on a slide, plus every album manifest JSON.
**Files:** `src/server/app.js:74-84` (`googlePhotosGate`), specifically `src/server/app.js:77`
```js
const dir = decodeURIComponent(String(req.path || '/').split('/')[1] || '');
...
if (dir && (await viewerAlbumDirs()).has(dir)) return next();   // :79
```
and the static mount `app.use('/google-photos', googlePhotosGate, express.static(dataPath('google-photos'), …))` (`app.js:449` prod, `:490` dev).

**Root cause:** the gate authorises on **only the first path segment** (`split('/')[1]`), but then hands the *unchanged* `req.url` to `express.static`, which resolves `..` **relative to the google-photos root**. A single `..` after a valid, enabled album name cancels that segment, so the file `express.static` actually serves is a *sibling* directory (a disabled album) or any file sitting at the google-photos root — while the gate still saw the enabled album and called `next()`. `express.static`'s own `..` protection only refuses escaping the *root*, which this never does.

**Reproduction (CONFIRMED on the throwaway, current HEAD `1c70bd9`):** album `cfgA` is enabled and used by an enabled `GOOGLE_PHOTOS_SLIDE` (dir `album-vz2zwb`); album `cfgB` is **disabled** (dir `album-euppce`). As a live viewer (holding only the `tt_live` cookie, via the tunnel stand-in):
```
GET /google-photos/album-euppce/pB.jpg                             -> 404   (gate works for a direct disabled-album hit)
GET /google-photos/album-vz2zwb/../album-euppce/pB.jpg             -> 200  "DISABLED-ALBUM-SECRET-PHOTO"
GET /google-photos/album-vz2zwb/../album-euppce.json              -> 200  {"albumId":"album-euppce","photos":[{... sourceUrl ...}]}
GET /google-photos/album-vz2zwb/%2e%2e/album-euppce/pB.jpg         -> 200  "DISABLED-ALBUM-SECRET-PHOTO"   (encoded dots, literal slash)
```
The `/api/google-album/cfgB/photos` route (which hands out the `/google-photos/album-euppce/...` URLs) correctly 404s for the viewer — but the attacker does not need it: `extractAlbumId` is a deterministic transform of the album URL (and for `photos.app.goo.gl` links a weak `album-<base36 of a 31-bit hash>`), and in any case a viewer can list the *enabled* album's manifest and simply walk `../<otherdir>/`. File names inside an album are UUIDs, but the **manifest JSON at `<dir>.json` lists them all** (and leaks each photo's real `googleusercontent.com` `sourceUrl` and the album `configId`), and is itself readable the same way.

**Ceiling (also confirmed):** bounded to the `data/google-photos/` tree — `/google-photos/album-vz2zwb/../../users.json` and `../../ceiling-probe.txt` both 404 (express.static refuses escaping its own root), so this is NOT arbitrary file read. Anonymous (no live cookie) is still 404 (falls to `localhostOrAuth`), so it is viewer-reachable only (plus kiosk/admin, which is intended).

**Impact:** defeats the just-shipped control; every live-view holder sees photos the school chose to keep off the TV (disabled albums, unused albums) and the manifests (direct Google URLs + structure). Chain: combine with any future stray file written into `data/google-photos/` (progress dumps, temp files) for wider read.

**Minimal fix:** authorise on the **resolved** target, not the first segment. In `googlePhotosGate`, reject any request whose decoded path contains a `..`/`.` segment (and empty segments) before `next()`, or compute `path.relative(GP_DIR, path.resolve(GP_DIR, '.'+req.path))`, take its first segment, and require THAT to be in `viewerAlbumDirs()`. (express.static `{ dotfiles: 'deny' }` does not help — there is no dotfile here.) Add a `test/live.test.js` case: viewer `GET /google-photos/<enabled>/../<disabled>/x.jpg` -> 404.
