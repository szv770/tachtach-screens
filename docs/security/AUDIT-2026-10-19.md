# TachTach-Screens security audit (2026-10-19)

The owner asked for this review. It only reports problems; no source files were changed. Dynamic tests ran only against a throwaway copy of the app on `127.0.0.1:3901`, with throwaway users created through `src/server/users.js`. A preloaded network guard blocked every outbound connection that was not to loopback. The real `data/` folder was never touched. To simulate a "LAN client", requests were sent from a non-loopback source address (`curl --interface`) to the loopback listener. Any secrets seen during testing are redacted here.

## Executive summary

| Severity | Count |
|---|---|
| Critical | 1 |
| High | 2 |
| Medium | 5 |

**Overall posture:** most of the design is solid. Sessions, links and devices are stored only as hashes. CSRF uses a double-submit token bound to the session by HMAC. Editors get fail-closed capability checks. TOTP codes cannot be replayed. `next=` is safe. Takeover HTML is escaped. The systemd units are hardened.
