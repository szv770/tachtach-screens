# TachTach-Screens — Security Audit (2026-10-19)

White-hat review of the owner's self-hosted kiosk/admin app (Node/Express, JSON
files, Raspberry Pi behind a Cloudflare Tunnel). Report-only. Dynamic tests ran
against a **throwaway copy** on `127.0.0.1` with all external network blocked and
a throwaway `users.json`; the real `data/` was never touched. The co-located
`saas-server`/`saas-admin` Mivtzah product got a lighter pass (noted at the end).

PoC transcripts: `docs/security/poc/README.md`.

## Executive summary

Overall posture is **good for a one-person shop**: fail-closed capability model,
hashed session/link/device tokens, bcrypt(12), mandatory admin TOTP with
single-use steps, per-person+address lockouts, session-bound double-submit CSRF,
a real SSRF guard on the embed probe, prototype-pollution-safe settings merge,
and tight upload content-types. Two issues stand out and should be fixed before
anything else, because **chained they let an unauthenticated device on the same
LAN read every password hash and TOTP secret.**

| Severity | Count |
|---|---|
| Critical | 0 |
| High | 2 |
| Medium | 4 |
| Low | 5 |

Top 5 (fix in this order):
1. **H1** Path traversal in `/api/rss/cache/:feedId` → arbitrary file read (`users.json`).
2. **H2** LAN hosts bypass `localhostOnly`/`localhostOrAuth` by spoofing `X-Forwarded-For` (TRUST_PROXY=1 + HOST=0.0.0.0).
3. **M1** `/api/rss/cache` GET is readable by *any* signed-in user (incl. View-only) — authz gap that makes H1 remotely reachable.
4. **M2** No `Content-Security-Policy` / HSTS / `X-Powered-By` removal on the admin & kiosk HTML.
5. **M3** `npm audit`: critical `tar`/`proxy-addr`, high `undici`/`sharp`/`bcrypt` chains in prod deps.

## High

### H1 — Path traversal → arbitrary file read in `/api/rss/cache/:feedId`
**Severity: High** (CVSS ~8.1; auth'd-or-local file read of the credential store)
**Files:** `src/server/app.js:282-292` (route 6e, `localhostOnly`) and
`src/server/routes/api.js:1241-1252` (`GET /api/rss/cache/:feedId`, behind `requireAuth`).

Both handlers build the path straight from the URL parameter:

```js
const filePath = path.join(PROJECT_ROOT, 'data', 'rss-cache', `${req.params.feedId}.json`);
const raw = await rf(filePath, 'utf-8');
res.json(JSON.parse(raw));
```

Express percent-decodes route params, so `feedId = "..%2Fusers"` becomes
`../users` and `path.join` resolves to `data/users.json`. Verified on the
throwaway instance:

```
GET /api/rss/cache/..%2Fusers
-> {"version":1,"users":[{"username":"admin","role":"admin",
     "passwordHash":"<RED>","totpSecret":"<RED>","totpEnabled":true,
     "sessions":[{"hash":"<RED>"}]}]}
```

Any JSON file the process can read is exfiltrable (`users.json`, `push.json`,
`activity.json`, `cache.json`). Because the handler `JSON.parse`s and returns the
content, it is a full read, not just existence.

**Fix:** validate the id against the known shape and reject separators before
touching the filesystem (apply to both copies):

```diff
-    const filePath = path.join(PROJECT_ROOT, 'data', 'rss-cache', `${req.params.feedId}.json`);
+    const id = String(req.params.feedId);
+    if (!/^[0-9a-f-]{36}$/i.test(id)) return res.status(400).json({ error: 'Bad feed id.' });
+    const dir = path.join(PROJECT_ROOT, 'data', 'rss-cache');
+    const filePath = path.join(dir, `${id}.json`);
+    if (path.relative(dir, filePath).startsWith('..')) return res.status(400).end();
```

(Same class of bug does **not** affect the google-album routes — those look an id
up in an array rather than building a path — nor uploads/fonts, which are served
by `express.static`. Confirmed.)

### H2 — LAN bypass of localhost gating via `X-Forwarded-For`
**Severity: High** (CVSS ~7.5; network-adjacent, unauth, info disclosure + abuse)
**Files:** `src/server/app.js:158-160` (`trust proxy` 1),
`src/server/middleware.js:74-100` (`localhostOnly`/`localhostOrAuth` compare `req.ip`),
`deploy/tachtach-server.service` (`HOST=0.0.0.0`, `TRUST_PROXY=1`).

`app.set('trust proxy', 1)` tells Express the request came through exactly one
trusted proxy, so `req.ip` is taken from the right-most `X-Forwarded-For` entry
supplied by the *immediate* TCP peer. Behind the Cloudflare Tunnel that peer is
`cloudflared` on loopback, which rewrites XFF — a tunnel client cannot forge
`127.0.0.1` (verified: 404). But `HOST=0.0.0.0` also exposes the server on the
LAN (a documented feature), and a LAN client is itself the immediate peer, so its
forged header is trusted:

```
curl --interface <lan-ip> -H 'X-Forwarded-For: 127.0.0.1' http://<pi>:3000/api/state       -> 200
curl --interface <lan-ip> -H 'X-Forwarded-For: ::1'        http://<pi>:3000/api/screen/state -> 200
```

So every `localhostOnly`/`localhostOrAuth` endpoint — `/api/state`,
`/api/screen/report|state`, `/api/google-album/:id/photos`, `/api/rss/cache/*`,
`/screen`, `/stream` — is reachable unauthenticated from any device on the school
Wi-Fi. `/api/screen/report` lets them spoof the kiosk's reported display size;
the google-album route lets them trigger outbound scrapes. **Chained with H1** it
is a pre-auth dump of the credential store from the LAN.

This is the *third* incident in this area (GOTCHAS.md "Localhost-gating breaking
remote access"); the root cause is that `req.ip` trust and true loopback are
conflated.

**Fix (defence in depth, pick both):**
- Gate on the **real socket** for localhost checks, not the proxy-derived ip:
  ```diff
  -  const localAddresses = ['127.0.0.1', '::1', '::ffff:127.0.0.1'];
  -  if (!localAddresses.includes(req.ip)) {
  +  const peer = req.socket.remoteAddress;
  +  const localAddresses = ['127.0.0.1', '::1', '::ffff:127.0.0.1'];
  +  if (!localAddresses.includes(peer)) {
  ```
  (`req.socket.remoteAddress` is the kernel peer and cannot be spoofed; the kiosk
  and cloudflared both connect over loopback, so they still pass.)
- Prefer binding the server to `127.0.0.1` and reaching the admin only over the
  tunnel / an explicit reverse proxy, instead of `0.0.0.0`; if LAN admin is
  required, put it behind the same auth rather than behind an IP check.

## Medium

### M1 — `/api/rss/cache` readable by every signed-in user (authz gap)
**Severity: Medium.** `src/server/routes/api.js:1241`. The authenticated copy is a
GET, and `canDo()` returns `true` for any GET by any role (`permissions.js:250`),
so a **View-only** editor — who is supposed to change nothing and see only the
normal admin reads — can call it, including the H1 traversal. Even without the
traversal, reading raw feed cache is outside the View-only intent. Fold the fix
for H1 in here, and consider requiring `feeds.edit` (or at least not exposing raw
cache) for this path. The kiosk already has the `localhostOnly` copy, so the
authenticated one is arguably redundant.

### M2 — No Content-Security-Policy / HSTS; `X-Powered-By` exposed
**Severity: Medium.** `src/server/app.js:163-168`. Only
`X-Content-Type-Options`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy` are
set. There is **no CSP** on `/admin` or `/screen`, no `Strict-Transport-Security`
(the app is served over HTTPS through the tunnel), and `X-Powered-By: Express` is
left on (verified via `curl -I`). A stored-XSS foothold (see L1) would be
unconstrained. HSTS matters because the admin login and session cookie travel
over the tunnel.

**Fix:** add a CSP (`default-src 'self'; frame-src https: ...; img-src 'self'
data: https:; object-src 'none'; base-uri 'none'`), `Strict-Transport-Security:
max-age=31536000` when `req.secure`, and `app.disable('x-powered-by')`. The
kiosk's Web-page slide frames arbitrary sites, so scope `frame-src` rather than
forbidding frames. Note the `/uploads` and `/google-photos` static mounts already
carry a tight per-file CSP — good.

### M3 — Vulnerable production dependencies (`npm audit`)
**Severity: Medium** (reachability-limited). Prod tree:
2 critical / 5 high / 3 moderate.
- `tar` (critical, hardlink path traversal) and `@mapbox/node-pre-gyp` come in via
  **bcrypt**'s install step — not reached at runtime, but update bcrypt to pull a
  patched `node-pre-gyp`/`tar`.
- `proxy-addr` (critical, IPv4-mapped-IPv6 trust-subnet spoofing) is **directly
  relevant** to H2 — it is Express's `trust proxy` parser. Upgrade Express.
- `undici` (high, response desync / cross-user disclosure) — transitively via
  fetch stacks; bump.
- `sharp` (high, libvips/libheif CVEs) — reachable: it processes **attacker-chosen
  image bytes** on upload. A malformed image could crash the worker or worse.
  Upgrade `sharp` and keep the 50 MB cap.
- `body-parser`/`qs`/`express` (moderate, qs DoS) — upgrade Express.

**Fix:** `npm audit fix`, then bump `express@^4.latest`, `sharp`, `bcrypt`,
`undici` and re-run `npm test`.

### M4 — View-only editor can push arbitrary content to admin preview iframes
**Severity: Medium→Low.** `src/server/routes/api.js:679` `POST /api/preview`
broadcasts the request body verbatim over SSE to all preview/admin-iframe clients
(`broadcastToAll('preview', req.body)`), and `canDo` allows it for everyone
(matches `PREVIEW` regex, `permissions.js:164,251`). A View-only or Messages-only
user can therefore inject arbitrary objects into other admins' live-preview panes.
Impact is bounded by how `preview` payloads are rendered (the preview iframe is
same-origin and reads them into React state), but it crosses the capability
boundary. Gate `POST /api/preview` behind at least `slides.edit`/`screen.control`.

## Low

### L1 — Takeover/announcement rendering uses `dangerouslySetInnerHTML`
**Severity: Low** (mitigated). `src/screen/takeover/TakeoverStage.jsx:113,116`,
`layouts.js`, `fit.js`. Announcement/takeover text (admin-authored) is built into
an HTML string and injected. Reviewed the builders: `layouts.js` escapes every
interpolated value through `esc()`/`ex()`/`eb()` (`&<>"'` → entities) and `fit.js`
re-escapes `& <` when it rebuilds word spans. No unescaped sink found. It stays a
Low because the whole subsystem is string-concatenated HTML one typo away from an
injection, and the authors are low-privilege editors (Messages-only can post).
Keep every new slot going through `esc`; a CSP (M2) would cap the blast radius.

### L2 — TOTP enrollment secret returned before confirmation / admin self-enroll
**Severity: Low.** `routes/auth.js:68-72`, `users.js:458-468`. An admin with only a
password (no 2FA yet) is handed a fresh TOTP secret + QR during login
(`totp_setup_required`) before proving anything beyond the password. That is the
intended bootstrap, but it means a stolen admin password alone lets the thief
enroll *their own* authenticator and pass the "mandatory 2FA" gate. Consider
requiring an existing admin to provision 2FA out-of-band, or at least alerting on
first-time enrollment. (TOTP replay itself is correctly prevented — `lastTotpStep`
blocks step reuse, `window:1`.)

### L3 — No rate limit on authenticated password-guess at `/account/password`?
**Severity: Low** (already handled). Verified `routes/team.js:157-162` *does*
throttle current-password guesses (`guessKey`, 6/15min) and `/account/2fa/disable`
likewise. Logging here for completeness — no action needed. The login flow has
IP (20/1h) + user+IP (8/15min) + the global 40/15min limiter. Good.

### L4 — Error handler can echo `err.message` when `err.expose` is set
**Severity: Low.** `src/server/app.js:450-452`. Generic 500s are masked, but any
error with `expose=true` (http-errors, some body-parser paths) is returned to the
client. Low risk today; keep an eye on it so internal paths/messages don't leak.

### L5 — `express.json` size asymmetry enables cheap memory pressure
**Severity: Low.** Most routes cap JSON at 16 kB, but `/api/schedule/{dates,blocks}`
is 256 kB and `/api/daily-words` is 512 kB (`app.js:184-187`,
`routes/daily-words.js:64`). These are authed + rate-limited (60/min), so a
logged-in editor could push ~30 MB/min of parse load. Bounded, but tighten the
daily-words cap (the list is ~20 kB) and keep the mutation limiter.

## Info / verified-OK

- **CSRF**: double-submit cookie HMAC-bound to the session token, `timingSafeEqual`
  compare, validated on mutating methods only, cookie `SameSite=Strict`. Logout is
  POST+CSRF. Missing/forged token → 403 (verified). Solid.
- **Prototype pollution**: `settingsMerge.deepMerge` has an explicit
  `__proto__/constructor/prototype` FORBIDDEN set (`settingsMerge.js:51,61`) and
  `PATCH /api/settings {"__proto__":…}` returns 403 for non-admin anyway (verified).
- **SSRF** (`embed-probe`, `embedCheck.isPrivateAddress`): http(s) only, blocks
  loopback/private/link-local/CGNAT/`::ffff:127.*`/`0.0.0.0`, re-resolves DNS and
  re-checks each redirect hop, 10 s abort. Note a gap: pure-IPv6 encodings of
  loopback like `::ffff:7f00:1` (hex form) and NAT64 `64:ff9b::7f00:1` are **not**
  caught by `isPrivateAddress` — but `dns.lookup` on a literal returns it unchanged
  and the fetch would target it; worth hardening `isPrivateAddress` to normalise
  IPv4-mapped/NAT64 hex forms. Marked Info because exploitation needs those exact
  literals and only yields header disclosure of a loopback service.
- **Uploads**: content-type allow-list + extension check, `sharp` re-encodes images
  to JPEG (strips embedded scripts/EXIF-polyglot risk), SVG allowed **only** for the
  logo (served from `/uploads` with `CSP default-src 'none'; img-src 'self'` and
  `X-Content-Type-Options: nosniff`, so a scripted SVG cannot execute in that
  context); `deleteMedia` requires a strict UUID (no prefix-match mass delete).
  PDF pages validated against a UUID-shaped allow-list. Good.
- **Open redirect**: `safeNext` only permits `/admin[/section]`.
- **Secrets**: no `.env`, TLS key, VAPID key, password or API token committed, in
  the tree or in ~400 commits of history. `data/users.json`, `tls/`, `push.json`,
  `auth.json` are gitignored. `mivtzah.js`/`saas` read keys from env, not literals.
- **systemd hardening** (`tachtach-server.service`): `NoNewPrivileges`,
  `ProtectSystem=strict`, `ProtectHome=read-only`, `ReadWritePaths=.../data`,
  `PrivateTmp`, runs as the pi user not root. Good. No `curl|bash` in the service
  path (only in interactive setup docs for NodeSource/Cloudflare, which is normal).
- **Kiosk Chromium flags**: no `--no-sandbox`, no `--disable-web-security`;
  `--allow-insecure-localhost` only for the loopback self-signed cert. Fine.

## saas-server (lighter pass)
- `src/app.ts`: `helmet()` on, CORS restricted to `ADMIN_ORIGIN` with credentials,
  session cookie `httpOnly+secure(in prod)+SameSite=strict`, 4 h expiry. Good.
- **Finding (Medium, in that product):** `SESSION_SECRET` falls back to the literal
  `'dev-secret-change-in-production'` (`app.ts:29`) and `DATABASE_URL` is read
  unchecked — if the Vercel env var is ever unset, sessions are signed with a
  public constant (forgeable). Make it throw when unset in production.
- Drizzle ORM is used for queries (parameterised); no `sql.raw`/string-built SQL
  found in `src`. CORS is not `*`. No committed secrets.
- Not exhaustively tested (out of primary scope, deployed separately on Vercel).

### M2 — Content-Security-Policy (fixed)
`src/server/csp.js`, mounted in `app.js` after the other security headers, sends an
**enforced** CSP on `/admin`, `/screen`, `/login`, `/invite/*`, `/signin/*` (uploads keep
their own stricter one). Scripts: `'self'` only, no `'unsafe-inline'`/`'unsafe-eval'`; the
admin's inline theme snippet moved to `public/splash/theme-init.js`, and the server-rendered
sign-in pages' inline scripts carry a per-request nonce (`withNonce`).
Allowances (each narrow and documented in `csp.js`):
- `style-src 'unsafe-inline'` — React/framer-motion inline `style=""` attributes; unavoidable.
- `fonts.googleapis.com` / `fonts.gstatic.com` on the kiosk and sign-in pages only (kiosk
  Google-font roles; sign-in page fonts). Not on `/admin`.
- Kiosk: `frame-src https: http:` (Web page / Mivtzah embeds of any site; http for a plain-http
  kiosk), `img-src ... https: http:`. Admin: `frame-src 'self'` (its same-origin live preview).
- `connect-src 'self'`, `worker-src 'self'` (service worker/web push), `manifest-src 'self'`,
  `media-src 'self' blob:`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`,
  `frame-ancestors 'self'`.
`CSP_REPORT_ONLY=1` flips it to Report-Only if a future page ever needs something new.

Verified with Playwright/Chromium on a throwaway data copy + throwaway admin: login page
(bad password -> inline script ran), 20+ admin sections incl. Media tabs, an image upload
preview, the mobile Quick-message sheet, the live-preview iframe, service worker
registration; the kiosk rotating through Zmanim/Limudim/Hayom Yom/Image/Web page/Mivtzah embed
(https iframes)/Schedule/Weather/Quote/Daily Word and then a takeover — **zero CSP violations**
(console + `securitypolicyviolation`); a negative control (injected inline script) was
blocked, so the detector works. Test: `test/csp.test.js`.

### Lows and hardening (pass 2)
- **L4** The global error handler no longer returns `err.message` at all (fixed text per status, `src/server/safeError.js`). Upload/logo/font rejections echo only messages created with `clientError()`; RSS preview, weather test and embed probe now give a short plain reason (`networkReason`) instead of the raw network error (hostnames/IPs).
- **L5** `/api/daily-words` JSON cap 512 kB -> 256 kB (measured: ~390 bytes/word, the 45-word starter list is 17 kB, so 256 kB is ~650 words). The admin panel also stopped uploading the archive (`history`, up to ~800 days) with every save; the server ignores it anyway. Schedule caps unchanged. Note: the `words` limit in `dailyWords.js` is still 1000, so a list that large would now exceed the body cap; lower it or raise the cap if that is ever wanted.
- **SSRF** `isPrivateAddress` now decodes IPv6 literals: IPv4-mapped (`::ffff:7f00:1`), NAT64 (`64:ff9b::/96`, `64:ff9b:1::/48`), 6to4, IPv4-compatible, Teredo, documentation, ULA, link/site-local and multicast are all judged by the IPv4 rules. It also stopped rejecting hostnames that merely start with `fc`/`fd`. Tests in `test/embedCheck.test.js`.
- **saas-server** `SESSION_SECRET` unset in production now throws at startup (`resolveSessionSecret`); development keeps the fallback with a warning. Vitest added (`saas-server/tests/sessionSecret.test.ts`) but not run here: `saas-server` has no installed `node_modules` in this environment; the function itself was exercised with Node's type stripping.
- **L2** On first-time enrolment the activity log gets "Linked a new authenticator app" and subscribed phones get a push ("New 2-step sign-in set up").
