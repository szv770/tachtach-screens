# Architecture detail

Read `CLAUDE.md` first. This is the deeper reference for the server internals.

## Request pipeline (`src/server/app.js`, in order)

1. `trust proxy` set if `TRUST_PROXY` env var present (required behind Cloudflare Tunnel — see GOTCHAS.md)
2. Security headers (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`)
3. `Cache-Control: no-store` on `/login`, `/admin`, `/api` (prevents a cached auth response looking like a logout)
4. `express.json({ limit: '16kb' })` — skipped for `/api/schedule/{dates,blocks}*`, which parse their own bodies at 256 kB (`routes/schedule-dates.js`) — then `cookie-parser`
5. `setupCheck` — 503 setup page for everything except `/login` + static assets until `data/users.json` has an admin (an old single-owner `data/auth.json` is migrated into it on first look)
6. Login rate limiter (40/15min per IP — a school shares one address; the real brute-force limits are per-person in `routes/auth.js`) on `POST /login`, `/login/totp`, `/login/totp-setup`, `/invite/:token`, `/signin/:token`
7. `authRouter` (login/logout/TOTP, `/invite/:token`, `/signin/:token`)
8. `localhostOrAuth` gate on `/screen` and `/stream`
9. `screenRouter` mounted on `/stream` (SSE)
10. `GET /api/state` — `localhostOrAuth` + `csrfProtection` (CSRF middleware runs here specifically to issue the `_csrf` cookie on load, not to validate — see below)
11. A few more `localhostOnly` kiosk-support endpoints: Google Photos album photos, RSS cache reads, screen-state report/read
12. Static file serving (`/assets`, `/fonts`, `/uploads`, `/google-photos`) + SPA `GET /screen`, `/error`, `/admin` (admin route also has `requireAuth` + `csrfProtection`)
13. `requireAuth` + `csrfProtection` + mutation rate limiter (60/min, skips GET/HEAD/OPTIONS) on all of `/api`
14. `scheduleDatesRouter` at `/api/schedule` (`src/server/routes/schedule-dates.js`: `dates` GET/preview/PUT all-or-nothing, `dates/:date` PUT/DELETE, `dates/:date/apply-block`, `blocks` CRUD, `zmanim?dates=`), then `apiRouter` — the actual CRUD handlers (`src/server/routes/api.js`, ~1300 lines, one section per admin resource: slides, schedule, messages, pinned, custom-days, media, photos, RSS, style, settings, screen-control)
15. `announcementsRouter` (`src/server/routes/announcements.js`) — `/api/announcements*` plus translating shims for the legacy `/api/messages`, `/api/pinned` and custom-slide POST (one release). Then `apiRouter` — the actual CRUD handlers (`src/server/routes/api.js`, ~1300 lines, one section per admin resource: slides, schedule, messages, pinned, custom-days, media, photos, RSS, style, settings, screen-control)
15. 404 handler, then a global error handler (multer file-size, JSON parse errors, generic 500)

## Auth model (`src/server/users.js`, `routes/auth.js`, `routes/team.js`)

- **People** live in `data/users.json` (never backed up, gitignored): `{ users[], links[], preauth[], lockouts{} }`. Each user: `id, username, name, role (admin|editor), passwordHash|null, totpSecret/totpEnabled, trustedDevices[], sessions[]`. `createUserStore({read,write,now})` takes injectable storage (tests in `test/users.test.js`); every write goes through one `tx()` queue.
- **Everything looked up by a token is stored only as a SHA-256 hash**: sessions (many per person), trusted devices, invite/sign-in links, pre-auth. The raw value exists only in the cookie / link.
- **Roles** (`src/shared/permissions.js`, shared by server + admin UI): admin = everything; editor = day-to-day content only. `enforceRole` (middleware, after `requireAuth` on `/api`) is **fail-closed**: an editor's write is allowed only if the path is on the `EDITOR_WRITE` allow-list; `/api/team` and `/api/activity` are admin-only even to read; `/api/me` and `/api/account/*` are for everyone. Paths are normalised (case, `//`, `%xx`, trailing `/`) before matching.
- **Capabilities, presets, per-person tweaks** (all DATA in `src/shared/permissions.js`): ~16 capability ids (`announcements.post/takeover/edit/delete`, `slides.edit/delete`, `media.upload/delete`, `feeds.edit`, `dailyWord.edit`, `screen.control`, `schedule.edit`, `customDays.edit`, `look.change`, `settings.change`, admin-only `team.manage`), each owning method+path rules (first match wins; the area's last rule is a catch-all). Presets: Admin (role, everything) / **Full editor** (default; also what a stored-nothing old editor gets, so existing editors behave exactly as before) / Messages only / View only. A person = `role` + `preset` + `overrides {grant[],deny[]}` stored on their `users.json` record (migration default at load; overrides sanitised to differ from the preset; `team.manage` is never grantable). `effectiveCaps(user)` / `can(caps,cap)` / `canDo(user,method,path,body)` are pure and shared; `/api/me` returns `caps`; `canOpenSection` derives tabs from caps (a tab opens if any of its caps is held). `enforceRole` stays fail-closed: unknown paths/odd spellings/dot segments denied, SELF endpoints unchanged, takeover writes also need `announcements.takeover`, look-only `PATCH /api/settings` needs only `look.change`. Admin-only `PATCH /api/team/:id {preset,overrides}`; admins can't be limited, last admin can't be demoted; logs "Changed <name>'s permissions". Changes apply on the next request (session user is read live). UI: Team -> person -> `PersonAccessSheet` (preset segmented control + closed Fine-tune toggles + SaveBar). Tests: `test/permissionsCaps.test.js`, `test/users.test.js`.
- **Login**: username (box only shown when >1 person) + password → if the person has 2-step on: `preauth` (5 min, stage `totp`) → code → session (skipped on a device holding a valid trusted-device cookie); admins without 2-step are walked through QR enrolment (stage `enroll`); editors without 2-step get a session straight away. 2-step is mandatory for admins, optional for editors. Codes accept ±1 step and a step can only be used once.
- **Invite link** (`/invite/<token>`, 7 days, single use): the person chooses a password (editors may skip it and use sign-in links only). **Sign-in link** (`/signin/<token>`, 60 min, single use): for a forgotten password; **GET only shows a confirm button, only the POST spends the link** (WhatsApp/iMessage previews fetch URLs). A new link of the same kind replaces the older unused one. The admin hands links over themselves (Team tab → copy / WhatsApp) — the server sends no email.
- **Lockouts**: per address 20 failures → 1 h; per person+address 8 failures → 15 min (so nobody can lock a colleague out from another address); counters restart after a quiet period and are pruned. Password-change / 2-step-off from a live session are throttled too.
- **Sessions**: 256-bit token, 30-day rolling (file rewritten at most hourly), 90-day absolute, up to 20 per person. Role change, password reset, "sign out everywhere", 2-step reset and removal all end sessions.
- **Activity log** `data/activity.json` (ring buffer of 500): `logActivity` middleware records every successful non-GET `/api` call as one plain-English line (`describe()` in `src/server/activity.js`; never request bodies) plus explicit lines for team actions and sign-ins. Announcements also carry `createdBy`/`updatedBy` display names.
- **Reset path**: `scripts/reset-admin-credentials.js` (`npm run reset-admin`; `--list`, `--user <username>`, `--reset-password`, `--reset-totp`); touches only `users.json`. Migration from the old `auth.json` keeps the owner's session and trusted devices.

## CSRF (`src/server/middleware.js` → `csrfProtection`)

Double-submit cookie, HMAC-bound to the session token: `_csrf` cookie = `nonce.hmac(nonce, sessionToken)`. Validated via `X-CSRF-Token` header on mutating methods only. The cookie is refreshed (not just validated) on every request where it's missing/invalid — deliberately wired into `GET /api/state` so the token exists before the admin SPA ever attempts a mutation.

## Scheduler (`src/server/scheduler.js`) — three tracks, all broadcast `cache-refresh` over SSE on completion

- **Track A** — one-shot `node-schedule` jobs at today's Chatzot, Plag HaMincha, Sunset, and Tzeit, each re-fetching zmanim so the screen only shows what's left today. The Sunset job additionally pre-fetches **tomorrow's** zmanim. A midnight job (00:01) rebuilds Track A for the new day. Toggle: `settings.scheduler.trackA`.
- **Track B** — one daily recurrence at an admin-configured `HH:MM` (`settings.scheduler.trackBTime`), full `fetchAll()`.
- **Track C** — unconditional `setInterval` full refresh every 30 minutes, always on, not admin-configurable. Acts as a safety net if Track A/B miss a fetch.
- All three are (re)initialized from `src/server/app.js` ~2s after server start, alongside Google Photos sync (`src/server/google-photos.js`), countdown alerts (`src/server/countdown.js`), RSS schedulers (`src/server/rss-scheduler.js`), the Mivtzah scheduler (`src/server/mivtzah-scheduler.js`), and daily storage cleanup (`src/server/cleanup.js`).

## SSE (`src/server/sse.js`, mounted via `src/server/routes/screen.js` on `/stream`)

- Two client pools: kiosk (`broadcast()`, max 20) and preview/admin-iframe (`broadcastToAll()` reaches both, max 10). Oldest-of-type client is evicted once its pool is full.
- 15s heartbeat sent as a real `data:` event (`type: 'heartbeat'`) — a bare SSE comment does **not** fire the client's `onmessage`, which previously made the client think the connection was stale after 20s of no real updates and reconnect-loop.
- Event types in the wild: `connected`, `heartbeat`, `settings-update`, `slides-update`, `announcements-update` (full items array; replaces `messages-update`/`pinned-update`, which the kiosk still accepts from an old server), `schedule-update`, `schedule-dates-update` (whole `schedule-dates.json` map; also in `/api/state` as `scheduleDates`), `countdown-start`/`-tick`/`-end`, `cache-refresh`, `screen-command` (`{action: pause|resume|blank|advance}`), `preview` (admin-iframe only, via `broadcastToAll`).

## Data files (`data/*.json`, via `src/server/storage.js`)

Atomic write: JSON → `.tmp` → `rename()`. Existing file copied to `.bak` first, **except** `auth.json`/`users.json` (never backed up — contain password hashes/TOTP secrets). On Windows/OneDrive, `rename()` can EPERM/EBUSY if the file is locked; falls back to a direct (non-atomic) write rather than crashing. File-level locking (`Map` of pending promises) serializes concurrent writes to the same file within one process.

Screen size: the kiosk (real screen only, not previews) POSTs `{display:{width,height,dpr,orientation,canvas}}` to the localhost-only `/api/screen/report` on load, resize and every 5 min; `screenState.js` keeps the sanitised value in memory (`getScreenDisplay()`, `reportedAt` added server-side) and `GET /api/state` returns it as `screenDisplay` (null until reported). `GET /api/media` (auth, any role) lists uploads; `processImage` shrinks into `uploadBox(display, orientation)` (1920x1080 until a screen reports).

Files: `users.json` (logins; legacy `auth.json` only read for migration), `activity.json` (who-did-what ring buffer), `settings.json`, `slides.json`, `announcements.json` (`{version, items}` — every slide/banner/side note/takeover post; see `src/server/announcements-model.js`), `messages.json` + `pinned.json` (legacy, emptied by the startup migration; originals in `data/legacy/*.pre-announcements.json`), `custom-days.json`, `schedule.json`, `schedule-templates.json`, `schedule-dates.json` (`{ "YYYY-MM-DD": { label, entries, updatedAt } }` — key present = that date overrides the weekly schedule even if empty; dates >60 days old pruned on write), `schedule-blocks.json` (`{ version, seeded, blocks: [{ id, name, label, entries }] }`; `seeded` marks the one-time default-category seeding so deleted categories don't come back), `zmanim-dates.json` (per-date zmanim fetched for the Claude prompt), the last three written via `src/server/scheduleStore.js` (one in-process read-modify-write queue), `quick-templates.json` (`{ version, seeded, templates: [{ id, ownerId (person id = personal, null = shared), text, textHe, blanks, focus, display, style, length, order }], recents: { <personId>: { name, person, place } } }`) and `saved-letters.json` (`{ version, letters: [{ id, ownerId, kind: 'letter'|'sicha', title, letter|sicha, style }] }`), both via the shared personal/shared store `src/server/ownedStore.js` (atomic via `storage.js`, one in-process queue, seeds written once under `seeded`), `google-albums.json`, `rss-feeds.json`, `fonts.json`, `cache.json`, plus `uploads/`, `fonts/`, `google-photos/`, `rss-cache/` directories.

## Fetchers (`src/fetchers/`)

All server-side, all write into `cache.json`. `chabad.js` (zmanim RSS + Hayom Yom/Chitas/Rambam HTML scrape via `cheerio`), `hebcal.js` (Hebrew date, Omer, parsha), `sefaria.js` (Daily Rambam/Tanya calendar), `rss.js` (generic feed + field mapping), `google-photos.js` (shared-album scrape, no OAuth), `mivtzah.js` (pulls from the co-located SaaS platform), `torahcalc.js`, `browserFetch.js` (puppeteer-core-backed fetch used where a plain HTTP request gets blocked — see GOTCHAS.md re: Cloudflare). `cache.rambam1/rambam3/seferHamitzvot` keep the RSS text as is (`displayEn`/`displayHe`); the kiosk structures it at render time with `src/shared/limudim.js` (sefer/halachos/perakim, Sefer HaMitzvos items; unparsable text falls back to the raw line), so no cache migration is needed.

## Schedule by date (`src/shared/scheduleResolution.js`, `schedulePaste.js`, `scheduleClaudePrompt.js`)

- `getEffectiveSchedule(schedule, scheduleDates, dateISO)` is the only place the "date override vs weekly" rule lives. Callers: kiosk `App.jsx` (feeds ScheduleSlide and the sidebar "starting in"), `countdown.js`, `/api/preview-state?date=`. It returns `resolvedFor` so ScheduleSlide doesn't re-filter by the real weekday; resolving twice is idempotent. Dates are local `YYYY-MM-DD` (noon-anchored `Date`s, never UTC).
- `parseScheduleText(text, { categories, today })` is used by the admin (day editor text mode) and the server (preview + apply re-parse). Errors carry line numbers and block apply; unknown categories become `newCategories` and are created on apply. `formatScheduleText` is its inverse ("Copy as text"); a round-trip test guards it.
- **Structured weekly save** (admin wizard / week view): `PUT /api/schedule/weekly` accepts `{ entries: [...] }` as well as `{ text }`. Each entry is validated like a pasted line (`buildWeeklyFromStructured` in `src/shared/scheduleWeekly.js`: name, time range, category match/creation, `alertBefore` 0-120, `days` codes or 0-6 indexes, `stages`); one bad entry rejects the whole save; the old week is saved as an `Auto-backup` template first (`planWeeklyReplace`). Wizard/week-view logic is pure: `src/shared/scheduleWizard.js` (patterns -> entries, overlap/gap/missing-time checks), `scheduleWeek.js` (copy a day, change one day), data tables `scheduleWizardPresets.js`.
- **Attention stages** (`src/shared/scheduleStages.js`; admin + data model only, the kiosk does not render stages 2 and 3 yet). Three stages around a block: (1) BEFORE = the existing `alertBefore` + `countdownDisplay` on an entry and `defaultAlert` on a category (NOT repeated in `stages`); (2) STARTED "Seder just started" and (3) SESSION "Now in session" badge live in an optional `stages: { justStarted?: 0-30 (minutes shown after the start, 0 = off), inSession?: boolean }` on a schedule entry (weekly or per-date) and on a category (the default for its entries). `resolveStages(entry, category)` -> `{ lead, leadDisplay, justStarted, inSession, sources }`: entry value, else category value, else built-in default (`justStarted` = 3 when `lead > 0` else 0; `inSession` = false), so old data behaves exactly as before. Whitelisted by `sanitizeStages` in `pickScheduleEntry`/`pickCategory` (`routes/api.js`) and `normalizeEntryInput` (paste/by-date); `PUT /api/schedule/entries/:id` with an empty `stages` clears the stored override. The paste TEXT format does not carry stages (use the admin UI); `formatWeeklyText` drops them. Kiosk track: call `resolveStages`, show stage 2 while `now - start < justStarted` min, stage 3 while `start <= now < endTime` when `inSession`.
- Startup (`app.js`): `ensureDefaultCategories()` adds the owner's default categories once, before `initCountdowns()`.
- Tests: `npm test` runs `node --test test/*.test.js` (schedule + announcements tests) (no framework). Don't use bare `node --test`: it would also pick up `scripts/test-hayom-yom.js`, which hits the network.

## Announcements (`src/server/announcements-*.js`, `src/shared/announcements.js`)

- One file, `data/announcements.json`, for Slide / Banner / Side note / Takeover posts. Shape and whitelist: `announcements-model.js` (`look.layout` bigwords|event|list|quicktime|quote|sicha|letter|classic, `look.style` any of the 26 takeover styles (`normalizeStyleId`: aliases, unknown -> classic), `look.animation` full|entrance|off (default full), `content.event/list/quicktime/quote/sicha/letter` (+ `target`/`targetHe` small top line; list items are strings or `{text,textHe,day,time}`), `when.startsAt/expiresAt/recurrence`, `status: 'draft'`, `takeover.group` share rotation).
- "Is it on screen now" is only ever decided by the pure `src/shared/announcements.js` (`isActive`, `status`, `nextChange`, `selectActive`, `pickTakeover`), used by kiosk, admin and server. Recurrence is wall clock in `settings.location.timezone`. Unit tests: `npm test`.
- Startup migration (`announcements-store.js` `ensureMigrated()`, kicked off in `createApp()`, awaited by `/api/state` and the routes): idempotent, lossless, backs up originals to `data/legacy/`. It runs in code because `deploy/update.sh` restores the Pi's own `data/*.json`.
- `/api/state` and `/api/preview-state` include `announcements` plus translated `messages`/`pinned` views for an old build (one release).
- **Quick messages and saved letters** (Phase 5A): `routes/quick-templates.js` (`/api/quick-templates`, `/reorder`, `/recents`) and `routes/saved-letters.js` (`/api/saved-letters`, own 96 kB body limit, exempted from the global 16 kB in `app.js`). Capability rule `announcements.post` on both prefixes (`permissions.js`, so view-only is refused by `enforceRole`); `ownedStore.js` then enforces ownership: a person sees only their own + shared records, others' personal ones answer 404, shared ones need `announcements.edit` (403 otherwise), `ownerId`/`id` can never come from a request body, ids are only compared to stored ids (never used as paths). Pure logic in `src/shared/quickTemplates.js` (validation, fill, `buildAnnouncement`), `quickTemplatesSeed.js` (the 9 starters, placeholders only), `savedLetters.js`, `letterParse.js` (paste-whole-letter splitter), `letterJson.js` (AI prompt + JSON validator); tests `test/quickTemplates.test.js`, `letters.test.js`, `banner.test.js`, `announceNav.test.js`. Posting always creates a normal announcement through `POST /api/announcements` (so `createdBy`, activity log, expiry and takeover capability checks apply); the `notice` layout is `content.notice` (+ model `modelNotice`, stage layout `notice`). Banner: `banner.mode` still|scroll, `banner.speed` slow|normal|fast on the item; defaults in `settings.banner`.
- `cleanup.js` deletes archived items `settings.announcements.archiveDays` (default 30) after they end.

## Screen design system and weather (Phase 4)

- **Roles, not values.** `src/shared/themes.js` defines each theme with five base values (bg, text, dim, muted, gold=accent). `baseRoles()` turns them into 8 CSS custom properties (`--bg --text --dim --muted --accent --onAccent --lift --liftPct`) set on `DesignRoot`; `globalCss.js` registers them with `@property` and derives `--raised --hi` with `color-mix()`. Panels add panel-local roles (`--ink --inkDim --fill --fillInk --accentText --line --past`, overridden per announcement style in `design/announceStyles.js`). Day/night = changing the 8 base values; the 4 s transition on `.tt-root` crossfades everything.
- **Day/night** (`src/shared/dayNight.js`): `settings.themeAuto` `{enabled, dayTheme, nightTheme, lightAt: alos|misheyakir|netz (default netz), darkAt: shkia|tzeis (default tzeis)}`, times from `cache.zmanim.today`, fixed 6:30/19:30 fallback. `dayPhase()` drives the sky tint.
- **Fonts**: `settings.fontRoles` (hebrewDisplay, hebrewBody, englishDisplay, englishBody, numerals, torahHebrew, torahEnglish) -> `--f-*` vars. Any font in `data/fonts.json` is `@font-face`d by `design/fonts.js` from `state.fonts`; Rubik/Manrope/Frank Ruhl Libre/EB Garamond are bundled from `@fontsource-variable/*` (no Google Fonts dependency for defaults). Other built-ins load from Google Fonts on demand.
- **Settings migration** (`normalizeSettings` in `settings-migrate.js` = stray keys + `migrateThemeSettings`), run at startup and on every `PUT /api/settings`.
- **Weather**: `src/fetchers/weather.js` (zip -> lat/lon via zippopotam.us/Hebcal once, Open-Meteo forecast) is called from `fetchAll()`; result in `cache.weather` (`{units,current,today,days,hours,location}`), last good value kept on failure. Settings `weather.enabled` (default on) / `units` / optional `zip`. `src/shared/weatherCodes.js` maps WMO codes to labels/icons. Rail readout + optional `WEATHER` slide (`src/server/builtin-slides.js` adds the row at startup).
- **Layout/seams**: `Layout.jsx` (rail + one panel + banner row), `Rail.jsx` (up-next from `getEffectiveSchedule`, within `rail.upNextMinutes`, hidden on the schedule page). **Takeover stage** (`src/screen/takeover/`, round 3b): announcements and takeovers are drawn by `TakeoverStage`. Flow: item -> `shared/takeoverModel.js` (layout content model) -> `layouts.js` (HTML string, text escaped) + `art.js` `renderArt()` (content box from `announceStyles.js`, static SVG layers with entrance/ambient animation data attributes) -> `dangerouslySetInnerHTML` once per content change -> `fit.js` `fitAll()` (one-shot binary searches per slot, README "Fit rules"; layout-px measurement, runs again on font load). Palettes are `.st-<id>` blocks of stage roles in `css.js` (`color-mix()` of the base roles; `.light` on the stage element = light theme family), scoped under `.tkr`. `StageBox` fits the stage into its container: `mode="canvas"` 1:1 (takeover), `mode="fit"` at the design size scaled down (slides, picker thumbnails). `effectiveAnimation(look.animation, settings.motion)` decides full / entrance / off (+ lively extras). New styles/layouts: see GOTCHAS "Takeover animation rules" ("Adding a style").

## Kiddush Levana (automatic announcement)

- Pure calculation + virtual item builder in `src/shared/kiddushLevana.js` (`kiddushLevanaState`, `kiddushLevanaItems`, `autoItemsFor`, `kiddushLevanaTable`); molad n = BaHaRaD + n * 765 433 chalakim, Jerusalem mean time (UTC+2:20:56) converted to an instant; every Hebrew month (Adar I/II too) is one index step. Tested against Rosh Hashana dates (dechiyos), eclipse new moons, DST, 3 vs 7 days, month rollover.
- Kiosk: `useAnnouncements(items, tz, { settings, cache })` appends the virtual items (ids `auto-kiddush-levana-note|banner|takeover`, `auto` + `readOnly` flags) before `selectActive`; nothing is written to `announcements.json` and no SSE event is needed (it is a function of the clock).
- Server: `src/server/kiddush-levana.js` `startKiddushLevana()` (from `app.js` startup) ticks every 30 s and records `{shown: {"<moladMs>:first|last": ISO}}` in `data/kiddush-levana.json`; `GET /api/kiddush-levana/shown` is `localhostOrAuth` (kiosk), `GET /api/kiddush-levana` + `PUT /api/kiddush-levana/settings` are authenticated (`announcements.edit` rule in `permissions.js`). `settings.kiddushLevana` is whitelisted in `settingsMerge.js`.
- Custom skips (`SKIP_CUSTOMS`) are keyed by Intl Hebrew month name + day; ICU's Hebrew calendar is off by a day for some years after 5806, irrelevant here (decades out), but the molad math does not use ICU.
