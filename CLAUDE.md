# TachTach-Screens — Agent Index

Digital signage for a Jewish school on a Raspberry Pi 5. One Node/Express process serves a kiosk display SPA (`/screen`) and a mobile-friendly admin SPA (`/admin`), synced live over SSE. No database — JSON files in `data/`. No Tauri, no TypeScript on this side (plain JS + React 18 + Vite, inline styles, no Tailwind).

**This repo has a second, mostly-independent product**: `saas-admin/` (React+TS+Vite) + `saas-server/` (Express+TS+Drizzle) is the "Mivtzah" SaaS platform, deployed separately to Vercel. TachTach only touches it via one feature: the `MivtzahLiveEmbedSlide` / `MivtzahLeaderboardSlide` iframe-embeds its public `/live` page. Fixing Mivtzah's own look/behavior happens entirely in `saas-admin`/`saas-server`, not here. `.worktrees/saas-build` and `.worktrees/saas-platform` are stale leftover dirs, not registered git worktrees (`git worktree list` doesn't show them) — don't assume they're live.

## Stack & run

Node/Express 4, React 18, Vite 6, Framer Motion, Sharp, node-schedule, bcrypt+otplib (TOTP). `npm run dev` (server :3000 + Vite :5173, proxied), `npm run build && npm start` for prod. `node setup.js` for first-time admin password — **never re-run it to reset a password, it wipes `data/`**; use `npm run reset-admin` instead.

## Non-negotiable rules

- **Fail closed.** Every route is gated: `/admin` + `/api/*` need `requireAuth`; `/screen` + `/stream` + a few kiosk-only `/api/*` endpoints use `localhostOrAuth`/`localhostOnly` (404, not 403, on reject — never leak route existence). See `src/server/middleware.js`.
- **Deliberate public exceptions (owner-approved 2026-10-21):** `GET /` (static homepage) and the opt-in **live view** (`/live`, `/live/:word`, see `src/server/live.js`). Nothing else may be opened to a visitor; a viewer cookie only ever unlocks the GET allow-list wired through `stateGate`/`kioskGate` in `app.js`.
- **`localhostOnly`/`localhostOrAuth` use `isLocalRequest()` (`src/server/middleware.js`): the TCP peer must be loopback AND no proxy header (`X-Forwarded-For`, `CF-Connecting-IP`, `Forwarded`…) may be present.** Never gate on `req.ip`: with `TRUST_PROXY` it comes from `X-Forwarded-For`, which any device on the LAN can forge (security audit 2026-10-19, H2). cloudflared connects over loopback but always adds those headers, so tunnel traffic is never mistaken for the kiosk. `TRUST_PROXY=1` is still needed behind the tunnel so rate limits and login lockouts see the real client address; it sets `trust proxy` to `'loopback'` (`src/server/clientIp.js`), so ONLY a loopback peer (cloudflared) may supply `X-Forwarded-For` and a LAN device's forged header is ignored (audit N2). See GOTCHAS.md.
- **CSRF**: double-submit cookie, HMAC-bound to the session token. The `_csrf` cookie is deliberately issued on `GET /api/state` (not just on mutation) — removing that breaks the first mutating request after every admin page load.
- **Banners never pause slide rotation; Takeovers always do; Boards replace slide content only.** This is intentional product behavior, not a bug.
- **`data/users.json` (and the legacy `auth.json`) is never backed up or touched by `git pull`.** Password/2-step reset only via `npm run reset-admin` (`scripts/reset-admin-credentials.js`), never `setup.js`.
- No Tailwind on the kiosk, and no hard-coded fonts or colours in screen components: they paint with the design roles (CSS custom properties set by `src/screen/design/DesignRoot.jsx` from `src/shared/themes.js` and `src/shared/fontRoles.js`). The approved round-2 look uses **Rubik** (Hebrew) + **Manrope** (English/numerals) + Frank Ruhl Libre / EB Garamond (Torah text) by default, every role swappable in admin to any built-in or uploaded font. No Inter/Roboto/system sans on the display. No infinite animations, blur, backdrop-filter or blend modes on the kiosk (Pi 5 at 4K, see GOTCHAS), except in takeovers/announcements and the **scrolling Banner** (one owner-approved ticker: one element, `translate3d` only, linear, seamless; see GOTCHAS "Kiosk design system rules"). Spec: `docs/design/2026-10-14-mockups-r2/`.
- **SaaS fit (every change, owner 2026-10-26).** This app becomes a multi-org cloud brain + thin Pi player (`docs/saas/CLOUD-PLAN.md`). Every new data file, route, setting, event, job or fetcher must pass the checklist in **`docs/saas/FIT-RULES.md`**: data only through a store module (never raw `data/` paths), declared scope (org/box/platform) and privacy class (names/secret), no hard-coded site/person values, a capability in `permissions.js`, files keyed by org, caches keyed by what they depend on, no module-level org state, an isolation test stub, viewer allow-lists opt-in. Where the code stands: `docs/saas/CODE-INVENTORY.md`; prep backlog: `docs/saas/NEXT-STEPS.md`.

## Working with agents

- **Keep agent usage small (owner priority).** Do small things yourself (read/search/edit/test). Delegate only chunky work, with a tight brief and a scope limit ("sample, don't exhaustively test"). Model per job: tiny lookups/checks → `haiku`; regular coding, admin/server work, tests, docs → `sonnet`; `opus` only for hard visual design/graphics/animation or hard logic/debugging. Max 1–2 agents at a time, 3 only if all are small. Tell agents to commit early (usage-limit cutoffs have cost rounds), to look at screenshots sparingly (images are expensive), and to prefer programmatic checks over screenshot sheets.
